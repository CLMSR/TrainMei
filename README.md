# TrainMei — Modular Final (Phase 6)

Final modularization of TrainMei from the verified monolithic reference. The project remains byte-editable as individual UTF-8 text files.

## Final architecture

```text
                    TrainingDataCore
                           ↓
                     Unified State
                           ↓
     ┌─────────────── Domain Modules ───────────────┐
     │ Day View · Workout Editor · Calendar · Plan   │
     │ Templates · Smart Training · OCR · Nutrition │
     │ Cycle Tracker · Recovery · Integrations       │
     └──────────────────────┬───────────────────────┘
                            ↓
                           UI
```

`TrainingDataCore` remains the single data/learning/context engine. `TrainMeiState` is the canonical runtime-state facade. Domain modules consume the state contract and do not create independent learning engines.

## Phase 6 extraction

`day-view.js` now owns the remaining Day / Workout View rendering boundary: day header fields, recovery controls, training blocks, non-running conditioning blocks, conditioning block creation and Day Context readiness rendering.

`training-planner-core.js` retains shared persistence, authentication, navigation, Supabase access and cross-domain event delegation.

## Architectural optimization

The migration preserves `window.__tp` as an internal compatibility layer but modules now resolve `window.TrainMeiState` first. This makes future changes to runtime state possible without every module reaching into planner internals.

## TrainMei Training Insights — 2026-10-09

This version adds a read-only **Insights** view integrated with the existing `TrainingDataCore`:

1. **Weekly Review** — completed sessions, logged time/RPE/recovery, plan adherence where explicit planned sessions exist, and a weekly session bar chart.
2. **Adaptive Training** — conservative, non-mutating progression suggestions based on repeated logged appearances of the same exercise. These are suggestions only and never edit a saved workout.
3. **Muscle Group Analytics** — weekly set volume and frequency estimated from exercise-name matching. Unmatched exercise names remain unclassified; this is a heuristic, not a validated biomechanical classifier.
5. **Pattern Discovery** — displays personal patterns and evidence/confidence generated by the existing `TrainingDataCore.learningProfile()`.

Architecture constraints:
- No separate learning engine or new storage.
- Existing TrainingDataCore remains the source for history and learned patterns.
- Missing data is shown as unavailable; no sleep, recovery, nutrition or planned sessions are fabricated.
- Existing app files and navigation are preserved. Insights uses `js/training-insights.js`; UI styles are consolidated into `css/style.css` and `css/responsive.css`, with no separate linked override stylesheets.

Validation performed:
- Node.js syntax check on every JavaScript file.
- Local script and stylesheet references in `index.html` checked.
- Duplicate HTML IDs checked.
- Browser/Supabase runtime behavior has not been exercised in this environment.

### Model quality principles

The model should become more useful through repeated comparable sessions and explicit outcome feedback: performance, energy, technique, RPE/RIR, pain, total time, recovery, nutrition timing and cycle context when relevant. Missing data stays unknown. Recommendations remain advisory; no saved workout is silently changed. Correlations are not treated as causal explanations.

### Validation scope for this build

Static syntax checks, HTML ID/reference checks, manifest JSON parsing, and local asset reference checks are performed on the generated package. Browser interaction, authenticated Supabase access, FatSecret sync and iOS rendering require runtime testing and are not represented as verified here.

## Weight Tracker, Weight % and FatSecret auto-sync (v5 experiment)
- Nutri Tracker retains the calorie/macro calculator and adds a dated Weight Tracker with backdated entries, edit/delete, a daily chart and a 7-calendar-day rolling average. A future date is rejected; a forgotten prior-day measurement can be entered later.
- Smart Integrations now has a dedicated **Weight %** launch card and workspace. Each exercise has its own card, editable reference 1RM, tested/estimated label, selectable load increment and a 95–50% table. The rounded usable load is shown alongside the exact calculation when rounding changes the value.
- Weight % reads the existing workout history through `TrainingDataCore`; it compares sessions whose normalized exercise names match and derives a conservative descriptive trend from Epley estimated 1RM. It also shows last-session load, sets, reps and volume. It does not silently change the reference RM or any workout. Name variants that do not match exactly may need to be logged consistently.
- Weight and RM data remain cached in `localStorage` for immediate use, and the app now supports account-level sync through the new tables in `supabase/migrations/20261010_weight_tracker_and_rm_profiles.sql`. **Apply this migration in the Supabase SQL Editor** to enable cross-device persistence. Until then, these records are device-local and the UI reports that cloud sync is unavailable/not configured. RLS limits each table to the authenticated owner.
- FatSecret now checks on authenticated app entry. If the latest backend sync is at least 2 hours old, it automatically refreshes yesterday and today, guarded against simultaneous runs. Failed attempts have a 15-minute retry cooldown; existing data is retained and a status message is shown. It still supports manual and range-based sync. This does not run while TrainMei is closed; it is entry-triggered, not a background server schedule.
- Weight tracking never writes body-weight records into FatSecret. These modules consume the existing shared TrainingDataCore / workout records rather than adding a separate learning engine.

Validation for v5: JavaScript syntax, unique HTML IDs, local references, CSS brace balance, a VM test of backdated weight entry and exercise progression, and a mocked FatSecret entry-sync/cooldown test. Browser/iPhone visual review, authenticated Supabase round-trip after migration, and live FatSecret OAuth/sync still require real-device/runtime verification.
